## 작업별 수정 범위와 완료 기준

### RC-01 문헌 버전·열람 근거 검증 통일

**완료 — 2026-11-18, 버전 1.0.1, 코드 커밋 `52aafc1`.**

- **확인된 현상** — 대표 문헌은 초록만 확보했지만 다른 버전의 본문을 읽은 경우, 근거 위치 검사는 통과하고 주장 검사는 거부한다. 기존 열람 위치가 있는 동일 버전에 새 위치를 가져오면 추가 위치가 검사에 반영되지 않는 사례도 있다.
- **수정 방법** — 주장·노벨티·근거 카드에서 실제 인용 버전을 같은 기준으로 선택한다. 동일 버전의 열람 위치는 중복을 제거해 병합하고, 버전이 다른 근거 위치는 해당 버전에 연결한다.
- **영향 범위** — `scripts/researchlib/literature.py`, `evaluation.py`, `output.py`, 문헌 가져오기와 근거 카드 테스트, 근거 형식 지침.
- **완료 기준** — 다른 버전의 유효한 본문 근거가 주장과 노벨티에서 모두 인정된다. 동일 버전의 추가 열람 위치가 인식된다. 미열람 위치·버전 불일치·제외 문헌은 검사에 걸린다. 같은 자료를 반복해서 가져와도 결과가 안정적이다.
- **기대 효과** — 근거 판정의 충돌과 반복 열람을 줄인다.

### RC-02 선택 후보의 공백·주장·문헌 연결 검증

**완료 — 2026-11-18, 버전 1.0.2, 코드 커밋 `ac86a87`.**

- **확인된 현상** — 계획과 단계 상태를 채운 상태에서 `claims`와 `gaps`를 모두 비워도 최종 검증이 통과한다. 후보가 어떤 공백에서 나왔는지 추적하는 필수 연결이 없다.
- **수정 방법** — 후보에 공백 ID 참조를 추가하고, 선택 후보 → 공백 → 주장 → 실제 열람 문헌의 연결을 검증한다. 근거 부족 상태에는 부족 사유와 다음 확인 작업을 연결한다. 근거가 부족한 후보의 최종화 정책을 평가와 보고서에서 일치시킨다.
- **영향 범위** — `output.py`, `evaluation.py`, 후보·공백 데이터 계약, 최종 검증 테스트.
- **완료 기준** — 근거 연결 없이 완료로 표시한 후보가 최종 검증에서 지적된다. 잘못된 ID·제외 문헌·연결이 끊긴 공백을 감지한다. 추천 후보가 없는 보고서는 부족 사유와 다음 행동을 기록하면 작성할 수 있다. 기존 초안은 읽을 수 있고 보완할 항목이 표시된다.
- **기대 효과** — 형식만 채운 제안을 걸러내고 연구 주제의 출발점을 추적한다.

### RC-03 자원 추정과 사용 가능 기간 대조

- **확인된 현상** — 파일럿·설계·데이터 이력이 빠진 후보도 일반 평가에서 통과할 수 있다. 합성 사례에서 기간은 2개월, 예상 학습은 200만 시간이어도 다른 조건을 채우면 통과한다.
- **수정 방법** — 필요한 준비 기록의 누락을 평가에 반영한다. 사용자에게 확인한 작업 기간과 사용 가능 GPU시간을 구조화하고, 조건별 실행·반복·평가 비용을 합산해 사용 가능량과 대조한다. 미확인 사용 가능 시간에는 확인 과제를 표시한다.
- **영향 범위** — `planning.py`, `evaluation.py`, `state.py`, 파일럿 명령·보고서, 자원 형식 지침.
- **완료 기준** — 시간 초과와 메모리 초과가 각각 표시된다. 미측정 후보는 조건부로 평가된다. 파일럿 실행 수와 설계의 비교 조건·반복 수가 일치하는지 확인한다. GPU 실험이 해당하지 않는 연구는 사유를 기록하고 적절한 작업량 기준을 사용한다.
- **기대 효과** — 장비 용량과 연구 기한을 모두 고려한 실행 가능성 판단을 제공한다.

### RC-04 후보별 문제 정의부터 기대 기여까지 연결

- **현재 상태** — 문제와 공백은 전체 분석에, 연구 질문과 실험은 후보 계획에 흩어져 있다.
- **개선 방법** — 후보의 앞부분을 문제 정의 → 기존 해결 범위 → 남은 공백 → 연구 목적 → 연구 질문 → 가설 → 검증 실험 → 기대 기여 순서로 구성한다. RC-02의 근거 연결을 재사용한다.
- **영향 범위** — `output.py`의 계획 항목·출력 순서, 후보 생성 지침, 데이터 계약, 최종 계획 검증과 테스트 자료.
- **완료 기준** — 선택 후보마다 위 흐름을 읽을 수 있고 질문과 실험이 연결된다. 문제 정의와 연구 목적의 누락이 표시된다. 기존 18개 계획 필드를 쓰는 초안도 읽을 수 있다. 추가 필드 수와 이름을 코드·지침·테스트에서 일치시킨다.
- **기대 효과** — 후보를 비교하기 쉬워지고 연구계획서·서론 작성에 필요한 논리를 재사용한다.

### RC-05 조건 변경에 따른 재검토 범위 조정

- **확인된 현상** — 데이터 조건을 바꿔도 평가 이후만 오래된 상태로 표시된다. 데이터 변경이 노벨티에 미치는 영향이 빠질 수 있고, 후보 하나의 파일럿 변경은 전체 평가에 영향을 준다.
- **개선 방법** — 변경 항목별 영향을 명시하고, 후보별 변경에는 영향을 받는 후보 ID를 기록한다. 기존 전역 단계 표시는 후보별 상태와 함께 일관되게 계산한다.
- **영향 범위** — `state.py`의 조건 갱신·무효화, `research.py`의 파일럿 기록, `evaluation.py`, 재개 지침.
- **완료 기준** — 데이터 변경으로 관련 공백·노벨티가 재검토 대상이 된다. 특정 후보의 파일럿 갱신으로 무관한 후보가 불필요하게 재검토되지 않는다. 선호 투고처만 바꾼 경우 문헌 분석은 재사용된다. 기존 전역 상태 세션도 처리한다.
- **기대 효과** — 오래된 판단을 재사용할 위험과 재검토 비용을 줄인다.

### RC-06 검색·캐시 집계 수정과 검색 지속 근거 기록

- **확인된 현상** — 다른 세션의 캐시를 처음 채택하면 전체 결과 예산은 1건을 사용하지만 갈래별 채택 통계에는 0건으로 집계된다.
- **수정 방법** — 외부 요청, 새로 예산을 사용한 결과, 기존 채택 결과의 재사용을 구분해 집계한다. 이후 최근 검색의 신규 관련 문헌과 남은 질문을 기록해 다음 검색의 필요성을 설명한다.
- **영향 범위** — `budget.py`, `search.py`, 검색 예약·기록 명령, 검색 이력 형식과 탐색 지침.
- **완료 기준** — 신규 캐시 채택과 재사용의 예산·갈래별 합계가 맞는다. 실패·초과 응답·재기록의 집계가 일관된다. 검색 지속·종료 시 남은 질문과 이유를 기록한다. 신규 결과가 없다는 이유만으로 노벨티를 확정하지 않는다.
- **기대 효과** — 예산 배분 오류와 가치가 낮은 반복 검색을 줄인다. 절감량은 RC-07의 비교 실행에서 측정한다.

### RC-07 유망 후보에 상세 검토 집중

- **현재 상태** — 지침은 7개 검토 역할과 후보별 상세 계획을 요구한다. 초기에 탈락할 후보에도 상세 작성 비용이 들 수 있다.
- **개선 방법** — 초기에 문제·질문·가까운 문헌·주요 실행 장애를 짧게 검토한다. 유망 후보부터 상세 노벨티·실험·투고처 검토로 확장하고, 순위를 바꿀 새 근거가 있으면 관련 후보를 다시 검토한다.
- **영향 범위** — `SKILL.md`, 후보·검색·출력 지침, 진행 상태 기록.
- **완료 기준** — 단계별 검토 깊이와 승격·보류 이유가 남는다. 최종 선택 후보에는 필수 검증이 적용된다. 같은 입력과 예산으로 기존 절차와 비교해 검색 요청 수·실행 시간·검토한 핵심 근거·누락 항목을 기록한다. 토큰 사용량은 환경이 제공하는 경우 측정한다.
- **기대 효과** — 최종 결정에 영향을 주는 근거와 불확실성에 작업을 집중한다. 실제 절감 효과는 비교 실행으로 판단한다.

### RC-08 후보 선택용 보고서와 상세 근거 연결

- **현재 상태** — 보고서는 평가 사전과 설계·데이터 이력 JSON을 그대로 보여 준다. 선택 후보 6개를 지정하면 최종 검증은 통과하지만 후보 상세는 5개만 출력되는 사례도 확인됐다.
- **개선 방법** — 보고서 앞부분에 후보별 문제·질문·방법·기여·주요 위험·다음 행동을 배치하고 상세 근거 카드에 연결한다. 선택 목록과 실제 출력 목록을 같은 기준으로 처리한다.
- **영향 범위** — `output.py`, `planning.py`의 첫 주 체크리스트, 보고서 지침, 내보내기 테스트.
- **완료 기준** — 사용자가 후보별 핵심 논리를 찾을 수 있다. 근거와 불확실성이 상세 기록으로 연결된다. 선택한 후보가 조용히 누락되지 않고, 보고서와 체크리스트가 동일한 선택을 반영한다. 내보내기 전후 상태 파일은 일치한다.
- **기대 효과** — 의사결정에 필요한 정보를 빨리 찾고 선택·출력 불일치를 방지한다.

### RC-09 의미 있는 효과와 표본·정밀도 계획 추가

- **현재 상태** — 주요 지표·표본 단위·반복 수·불확실성 방법은 있으나, 어떤 크기의 효과가 의미 있는지와 확보한 표본으로 판단 가능한지의 연결이 약하다.
- **개선 방법** — 의미 있는 효과의 기준, 표본·사건 수, 목표 정밀도 또는 적절한 검정력 근거를 연구 설계에 연결한다. 계산에 필요한 정보가 부족하면 파일럿에서 측정할 항목을 지정한다.
- **영향 범위** — `planning.py`, 설계 지침, 평가 계획·성공 기준·자원 추정의 연결.
- **완료 기준** — 기준값의 근거와 가정을 기록한다. 환자·영상·반복 실행 단위의 차이를 처리한다. 정량적 검정이 해당하지 않는 연구에는 해당 분야의 판단 기준과 사유를 적는다. 필요한 반복·표본 변경이 RC-03의 자원 추정에 반영된다.
- **기대 효과** — 실험이 완료돼도 질문에 답하지 못하는 설계를 줄인다.

### RC-10 투고 일정과 실험 완료 예정일 대조

- **현재 상태** — 재확인은 저장된 확인일의 경과 기간을 검사한다. 일정은 자유 서술 값이어서 이미 지난 마감이나 연구 종료 후 필요한 원고 준비 시간을 자동 대조하기 어렵다.
- **개선 방법** — 학술대회의 회차·트랙별 마감과 시간대를 구조화하고, 실험·원고 준비 예정일과 대조한다. 복수 제출 단계가 있으면 해당 경로의 순서를 기록한다. 날짜가 미확인인 경우 공식 공고를 확인할 작업을 남긴다.
- **영향 범위** — `journals.py`, 투고처 데이터 계약, `journal-recheck` 출력과 보고서, 투고처 검토 지침.
- **완료 기준** — 지난 마감·회차 불일치·시간대 차이·실험 완료 후 준비 시간을 처리한다. 상시 접수 저널과 마감이 있는 학술대회를 적절하게 표시한다. 기존 자유 서술 일정은 읽고 구조화가 필요한 부분을 표시한다.
- **기대 효과** — 실제 일정에 맞는 투고 후보를 비교하고 마감 착오를 줄인다.

## 순차 실행 방법

1. 체크리스트와 실행 기록을 읽어 완료 항목을 확인한다. 다음 실행 대상은 가장 앞선 미완료 항목이며, 완료 항목의 변경·검증 결과를 재사용한다. 사용자가 완료 항목의 재검토를 요청하거나 새 회귀 오류가 발견되면 그 이유를 실행 기록에 남긴다.
2. 해당 항목의 호출 경로·검증·내보내기·관련 지침을 읽는다. 오류 수정은 재현 사례를 먼저 확보한다.
3. 해당 항목을 구현하고 완료 기준에 해당하는 회귀 테스트 또는 동작 확인을 수행한다.
4. 영향을 받는 데이터 계약·스킬 지침·예제를 함께 갱신한다. 기존 세션은 읽을 수 있게 하고 미확인 정보를 임의로 채우지 않는다.
5. 검증 결과와 커밋 식별자를 아래 실행 기록에 남기고 체크리스트를 갱신한다. 해결하지 못한 완료 기준이 있으면 미완료로 기록한다.
6. 다음 항목으로 진행한다. 설치·공개 반영 시 실제 변경 범위에 맞는 버전과 설치본을 확인한다.
