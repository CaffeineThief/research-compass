## 순차 실행 방법

1. 체크리스트와 실행 기록을 읽어 완료 항목을 확인한다. 다음 실행 대상은 가장 앞선 미완료 항목이며, 완료 항목의 변경·검증 결과를 재사용한다. 사용자가 완료 항목의 재검토를 요청하거나 새 회귀 오류가 발견되면 그 이유를 실행 기록에 남긴다.
2. 해당 항목의 호출 경로·검증·내보내기·관련 지침을 읽는다. 오류 수정은 재현 사례를 먼저 확보한다.
3. 해당 항목을 구현하고 완료 기준에 해당하는 회귀 테스트 또는 동작 확인을 수행한다.
4. 영향을 받는 데이터 계약·스킬 지침·예제를 함께 갱신한다. 기존 세션은 읽을 수 있게 하고 미확인 정보를 임의로 채우지 않는다.
5. 검증 결과와 커밋 식별자를 아래 실행 기록에 남기고 체크리스트를 갱신한다. 해결하지 못한 완료 기준이 있으면 미완료로 기록한다.
6. 현재 실행 대상은 후속 보완 A-01~A-06이다. 가장 앞선 미완료 항목부터 순서대로 진행하고, 6건을 모두 마친 뒤 전체 회귀·최종 내보내기·설치본 대조를 수행한다. 추가 버전과 공개 반영은 해당 작업 시점의 사용자 지시를 따른다.

기본 회귀 검사는 저장소 루트에서 실행한다.

```sh
python3 -m unittest discover -s tests -v
```

최초 기준선은 합성 자료와 모의 검색을 사용하는 테스트 55개 통과다. RC-01~RC-10을 거쳐 111개로 보강했고, 2026-11-19 재검증에서도 소스·설치본의 기존 111개 검사가 각각 통과했다. 다만 추가 사례 6건이 문제를 드러냈으므로 기존 검사 통과만으로 모든 설계가 정상이라고 판정하지 않는다. 각 보완의 재현 사례를 정식 회귀 검사에 추가해야 한다. RC-02 당시 개별 공개·설치 이후 1.0.0 복원, RC-01~RC-10 통합 후 1.0.1 공개·설치의 이력은 아래에 보존한다.
