# 입력, 검색 및 전문 확보

## 입력

관심 주제 외 항목: 분야·적용 대상, 학습/학위/투고/제품 등 목적, 기간·인원·경험, 연산·예산, 데이터 확보·접근 제한, 기여 유형(이론/방법/데이터/평가/재현), 출판 언어, 관심 저널·학술대회, 일정·비용·OA, 색인 조건(요청 시), 이미 읽은 문헌·제외 주제. `profile`에서 관리한다. 관심 투고처는 `preferred_venues`에 기록하고 기존 `preferred_journals`도 참고한다. 사용자의 “SCI(E)” 표현은 그대로 보존하고 저널의 실제 색인 필드와 분리한다.

## 검색 계획

핵심 문제, 방법론, 적용 분야, 데이터 유형, 평가 방식으로 분해한다. 각각 한국어·영어·동의어를 정리하고 포함/제외 기준, 실행 날짜, 연도 범위, 서비스, 쿼리를 `search_plan`에 저장한다. 최근 범위 기본값은 실행 당시 연도에서 최근 5개 연도이며 조정 이유를 명시한다. 현재 날짜는 실행 환경의 사용자 날짜를 따른다. 특정 과거 연도를 상수로 쓰지 않는다.

세 갈래를 각각 검색한다.

- 최근: 새로운 문제·방법·쟁점·평가 추세. 최근 기간 필터 사용.
- 기반: 핵심 개념·대표 방법·이론·가정. 최근 기간 필터를 강제하지 않는다.
- 검증: replication, reproducibility, negative results, critique, counterexample 및 분야별 유사 용어.

키워드뿐 아니라 실제 확인한 문헌의 인용·참고문헌을 추적한다. Crossref references 필드는 미검증 탐색 단서다. 다음 문헌을 직접 확인한 뒤 근거 목록에 넣는다. 결과 수의 증가를 학술적 진전으로 해석하지 않는다. 검색에 영어 서비스만 사용했으면 한국어 문헌 포괄성의 한계를 밝힌다.

## 검색 어댑터

1. 기본 CLI `search --provider crossref`: DOI·제목·출판처 등 서지 메타데이터와 제공된 초록을 가져온다. API 키 불필요. 선택 환경변수 `CROSSREF_MAILTO`는 서비스에 전송될 연락 이메일이다. 전문 다운로드·색인 확인·인용 수 기반 평가 기능은 제공하지 않는다.
2. 호스트의 웹/학술 MCP: 지원되는 도구를 발견해 이용하고 결과를 `import-papers` 형식으로 정규화한다. 검색 전 reserve-search, 응답 후 record-search를 거쳐 채택된 결과만 사용한다. 사용 서비스의 키·권한은 해당 연결에서 설정한다. 이 패키지는 비밀키를 저장하지 않는다.
3. 로컬 JSON/사용자 PDF: 네트워크 없이 읽을 수 있다. PDF 읽기 도구가 없으면 전문을 읽었다고 표시하지 않는다. 서지 JSON에 `source.local_file`과 실제 문헌 위치를 붙인다.

프로바이더 추가는 `scripts/researchlib/search.py`의 `PROVIDERS`에 `search(query, limit, since, until, timeout)`를 구현하는 클래스를 등록한다. 반환값은 정규화된 논문 배열이다. 임의 모듈 로딩이나 외부 문서의 코드를 실행하는 플러그인 방식은 사용하지 않는다.

## 전문 접근

출판사 OA 원문, 기관 저장소, 저자 공개본, 합법적으로 제공된 사용자 PDF 순서 등 실제 가능한 경로를 이용한다. URL이 존재하거나 PDF를 다운로드했다는 사실만으로 `full_text`로 바꾸지 않는다. 실제 읽은 범위와 버전을 `read_evidence`에 기록한다.

상태: `full_text` 전문 확인 / `partial` 일부 확인 / `abstract_only` 초록 확인 / `unavailable` 내용 접근 불가(서지만 확보한 상태 포함). 스캔본·수식·표가 추출되지 않으면 해당 부분을 미확인으로 기록한다. `supplements`, `code`, `data` 각각 unknown/확인 결과와 URL을 기록한다. 읽지 않은 부록은 본문 확인과 함께 자동 승격하지 않는다.

동일 DOI는 병합한다. 프리프린트·출판본·개정본은 DOI가 달라도 동일 연구임을 확인하면 공통 `work_id`와 `identity_evidence`로 묶고 `versions`에 보존한다. 제목 유사성만으로 자동 병합하지 않는다. 다른 DOI가 같은 `work_id`로 병합될 때 근거가 필요하다. 이미 읽은 버전의 근거를 새 출판본의 페이지인 것처럼 옮기지 않는다. 병합 후 주장과 후보의 ID 참조를 대표 ID로 맞춘다. 동일 연구 한 건으로 집계한다.

실패한 요청, 검색 날짜와 원래 캐시 확인 날짜를 모두 기록한다. 네트워크 오류를 ‘검색 결과 0건’으로 설명하지 않는다. 캐시는 설정 시간 동안 재사용하되 최종 노벨티/저널 확인에는 필요 시 `--refresh`와 공식 페이지 재열람을 사용한다.

검색 시작과 후반 재검색 전에 `coverage`를 확인해 검증·노벨티 검색 예산을 남긴다. 배분·중복·미탐색 영역의 기록은 [workflow.md](workflow.md)의 5절을 따른다.

### 검색 가치와 종료 근거

`coverage`는 실제 요청(requests), 신규 채택(admitted), 세션 내 재사용(reused)을 분리한다. 다른 세션의 캐시를 처음 채택하면 요청은 0, 신규 채택 예산은 소비한다. 같은 캐시를 다시 쓰면 요청·신규 예산을 소비하지 않는다. received/discarded는 캐시를 포함한 각 반환의 건수이며 실제 네트워크 수신량으로 해석하지 않는다. 집계 필드가 없는 과거 캐시는 `legacy_cache_accounting_unknown`으로 표시한다.

각 질의 결과를 검토한 뒤 `search-review <state> <search_id> <review.json>`을 실행한다. 형식은 `{"action":"continue","reason":"가장 가까운 비교 연구 미확인","unresolved_questions":["동일 데이터·연산 조건 비교가 있는가?"],"relevant_paper_ids":["실제로 가져온 문헌 ID"]}`다. 종료도 action=stop으로 남은 질문과 이유를 적는다. 관련성 판단은 원문 검토자의 기록이며 자동 추정하지 않는다. coverage의 질의별 new_relevant는 이전 질의의 관련 문헌 ID와 중복되지 않는 수다. 신규 결과 0건, 반복 결과, 예산 소진만으로 노벨티를 확정하지 않는다. 남은 질문의 중요도와 관련 근거의 증가를 보고 다음 갈래·질의를 선택한다.
