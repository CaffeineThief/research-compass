# 문헌 분석 및 공백 도출

문헌마다 `papers[].analysis`에 연구 질문, 해결 문제, 핵심 주장·기여, 방법·주요 가정, 데이터·실험·비교 기준, 결과·적용 범위, 재현 조건, 다른 연구와의 공통점·차이를 저장한다. 중요한 내용은 `claims`의 ID를 참조한다. 서지정보만 있으면 내용 분석을 보류한다.

주장의 `evidence`마다 문헌 ID와 위치(논문 인쇄 페이지 / PDF 뷰어 페이지를 구분, 절 제목, 표·그림 번호, 부록)를 기록한다. 웹 문서는 절 제목 등 대체 위치를 쓴다. 부분 확인 상태라면 읽은 절 밖으로 일반화하지 않는다. 인용문은 필요한 최소 부분만 쓰고 나머지는 근거 위치를 붙여 요약한다.

한계는 다음 중 하나로 분류한다.

- `author_acknowledged`: 저자가 인정한 한계. 해당 절·문구를 확인한다.
- `empirically_confirmed`: 다른 연구가 실험으로 확인한 한계. 원 연구와 검증 연구의 ID·평가 조건을 함께 연결한다.
- `agent_inferred`: 에이전트가 추론한 잠재적 한계. 미검증임과 확인 방법을 명시한다.

결과가 충돌하면 `conflicts`에 양쪽 주장 ID, 데이터·대상·척도·가정 차이, 해소 여부를 기록한다. 다수 의견이나 에이전트 합의로 한쪽을 참으로 판정하지 않는다. 충돌 해소에는 원문이나 추가 검증 근거가 필요하다.

종합 분석은 주요 흐름, 널리 쓰는 방법·평가, 반복 한계, 상충 결과, 검증되지 않은 가정, 데이터·평가·재현 공백, 타 분야 연결 가능성을 다룬다. `gaps`마다 관련 주장·문헌, 중요성, 기존 해결 시도, 남은 이유, 근거 강도, 불확실성을 쓴다.

‘논문에서 실험하지 않음’은 그 자체로 가치 있는 공백이 아니다. 현실적 사용 조건/이론적 예측/측정 편향 등 왜 해당 조건을 연구해야 하는지 독립적인 이유와 예상 학술적 가치를 제시한다. 확인한 선행 연구와 제안 가설을 분리한다.

기존 분석은 확인 버전·원문 위치·내용 지문 또는 로컬 파일 수정 정보와 함께 재사용한다. 새로운 자료가 기존 주장을 바꾸면 관련 공백·후보·계획·투고처를 `stale` 처리하고 대조한다.

근거 카드의 버전·짧은 발췌·해석 및 열람 위치 연결은 [workflow.md](workflow.md)의 1절을 따른다. 최종 카드 검증은 실제 읽은 위치를 대조하며, 내용 진위를 자동 인증하지 않는다.

후보를 도출하면 해당 후보의 `gap_ids`에 공백 ID를 연결한다. 각 공백의 `claim_ids`가 실제 문헌 근거로 이어지는지 확인하고, 연결이 부족한 부분은 후보의 부족 사유와 다음 확인 작업으로 남긴다.

분석 과정에서 주제를 좁혀야 한다고 판단하면 [후보 검토](candidates.md)의 범위 축소 가치 검토로 이어 간다. 좁힌 뒤에도 새로 알게 될 내용과 원래 문제에 남는 의미를 확인한다. 해결할 문제가 사소해졌다면 조건을 더 추가하기보다 원래 질문과 대안을 다시 검토한다.
