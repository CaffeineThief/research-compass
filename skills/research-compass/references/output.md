# 최종 산출물과 재개

진행 단계를 사용자에게 짧게 보여 주면서 계속 실행한다: 입력·검색 계획 → 문헌·접근 상태 → 근거 분석 → 추세·공백 → 검증·평가 → 계획 → 투고처. 필요한 제약 확인 외에는 단계마다 일괄 승인을 요구하지 않는다. 주제 선택을 요청한 사용자의 경우 후보 비교까지 만든 뒤 선택을 받는다.

최종 제안은 근거가 충분한 2~5개를 목표로 한다. 0~1개뿐이면 그대로 보고하고, 부족한 데이터·접근·검증·자원 및 다음 행동을 제시한다. 조건부 후보와 탈락 후보를 통과한 추천으로 포장하지 않는다.

각 후보의 앞부분에는 `gap_ids → claim_ids → 문헌 ID·버전·열람 위치`를 표시한다. 근거 연결이 부족하면 `gap_review`의 사유와 다음 확인 작업을 보여 준다.

각 후보는 다음 23개 계획 필드를 작성한다. 앞의 8개는 연구의 논리 흐름이며 후보 설명 맨 앞에 같은 순서로 표시한다.

1. problem: 문제 정의
2. prior_work: 기존 연구의 해결 범위
3. research_gap: 남은 연구 공백
4. objective: 연구 목적
5. question: 한 문장 연구 질문
6. hypothesis: 검증 가능한 가설
7. minimum_experiment: 최소 검증 실험
8. expected_contribution: 기대 기여
9. importance: 연구의 중요성
10. difference: 가장 가까운 선행 연구와 차별성
11. reading_order: 핵심 선행 연구와 읽는 순서
12. reading_sections: 확인할 절·방법·실험
13. prerequisites: 개념과 사전 지식
14. data_plan: 데이터 확보 계획
15. method: 방법론과 구현 단계
16. evaluation_plan: 비교 기준·지표·통제 조건
17. robustness: 제거 실험·민감도·통계 검증
18. decision_rules: 성공·수정·중단 기준
19. schedule: 단계별 일정과 산출물
20. resources_risks: 자원과 주요 위험
21. fallback: 실패 시 대체 접근
22. venues: 예비 투고처와 근거
23. negative_result_value: 예상과 다른 결과에서 얻을 지식

문제와 기존 해결 범위는 gap_ids로 연결된 문헌의 확인 범위에 근거한다. 연구 목적은 이 공백에서 무엇을 밝힐지 설명하고, 연구 질문의 비교 대상·조건·관측 결과가 가설과 minimum_experiment에서 어떻게 검증되는지 구체화한다. expected_contribution은 예상되는 지식·방법·자료의 기여와 적용 범위를 적으며, 미검증 결과를 확정하지 않는다. 기존 18개 필드 초안은 읽고 추가 5개 필드의 누락을 표시한다. 최종 선택 후보에는 23개 필드가 필요하다.

비교표에 상태·평가기준별 근거·불확실성·가중치·종합점수를 제공하고 탈락 후보 이유를 남긴다. 계획에 빠진 정보가 있으면 완성된 계획이라고 하지 않는다. `export`는 저장된 값을 Markdown/BibTeX/RIS로 변환할 뿐 연구 내용이나 누락 정보를 자동 생성하지 않는다.

`report.md`를 초안으로 내보낸 뒤 구조화된 근거와 일치하는지 검토하여 읽기 좋게 다듬을 수 있다. `state.json`을 원본으로 유지하고 보고서만 바꾸어 근거와 불일치하게 만들지 않는다. `references.bib` 또는 `references.ris`와 `state.json`(검색 이력 포함)을 함께 제공한다. 저장 경로를 최종 답변에 링크한다.

변경 시 갱신 범위: 논문 제외/추가 → 분석 이후, 분야·대상·기여 변경 → 검색 이후, 자원 변경 → 평가 이후, 선호 투고처·언어·색인·비용·OA 목표만 변경 → 평가 이후(venue_fit 재평가), 새 유사 선행 연구 → 노벨티 이후. 무관한 원문 읽기와 검색은 캐시로 재사용한다. `stale`가 남아 있으면 최신 결과라는 표현을 쓰지 않는다.

최종화에는 [workflow.md](workflow.md)의 7절을 적용한다. `validate --final`로 보고서 메타데이터·선택 후보 계획·실행 기록·근거 카드를 검사한 뒤 `export --final --format all`을 실행한다. `evidence-cards.md`와 `first-week.md`도 제공한다. 조건부 후보를 포함한 제안의 완성과 실험 착수 가능성을 구분한다.

최종 선택 후보의 공백·주장·실제 열람 문헌 연결을 검증한다. 연결이 부족하면 보완 과제를 포함한 초안으로 제공한다. 추천할 후보가 없으면 부족 사유와 다음 행동을 담은 최종 보고서를 작성할 수 있다. 데이터·자원 등 실행 조건의 미확인으로 조건부인 후보는 근거 연결을 갖춘 상태에서 최종 제안에 포함할 수 있다.

### 요약과 상세의 선택 일치

보고서는 후보별 문제·질문·방법·기대 기여·위험·다음 행동을 먼저 보여 주고, 후보 상세 앵커와 근거 카드·첫 주 작업으로 연결한다. 상세의 JSON 산정 근거는 접어서 보존한다. 요약은 저장된 기록에서만 가져오며 누락 정보는 미정으로 표시한다.

명시적 report.selected_candidate_ids는 순서와 전체 개수를 보고서·체크리스트에 그대로 적용한다. 초안의 탈락 후보 선택도 숨기지 않고 rejected로 표시하며 최종 검증은 거부한다. 중복·없는 ID는 초안에서도 오류다. 선택 필드가 없는 기존 초안은 순위순 비탈락 후보 최대 5개를 두 산출물에 동일 적용한다. 빈 배열은 후보 없음이다. export는 원본 상태를 변경하지 않는다.
